# Zen Compact Transparent HDR Guard v0.3.9 — macOS context menu rendering and corner cleanup

## Changes

- Fix the experimental default-OFF context-menu paint from v0.3.8: Firefox `popup.css` actually reads `--panel-background-color` and `--panel-text-color` on `menupopup::part(content)`, not only legacy `--panel-background` and `--panel-color`. HG now sets the effective variables and the content background directly, keeping its existing HG colour, transparency and first-frame custom blur (for example 10px).
- Prevent obvious dark or square outlines at the four rounded menu corners against white pages: the macOS popup widget's opaque `Menu` underlay, window shadow and CSS popup border/shadow are reset to transparent/none **only** on explicitly identified right-click menus and nested context submenus. Keep the native Firefox menu corner radius and layout unchanged. On a flat white page real glass can still look uniform; do not treat missing visible texture as proof blur is broken.
- **Keep Zen Context Menu MOD installed and its `Zen's own menus on macOS` setting enabled** to preserve all desired sorting, menu-item hiding and icon layout. HG only styles the popup surface. Optional Zen Context Menu `Apply Zen workspace gradient` and `Apply Zen accent color` may be turned off to avoid competing background paints, without disabling the entire MOD.

## SDR/HDR and Zia compatibility

- Do not touch Zia, Zen Site Folders, PiP, sidebar/card/popup features, Glance, browser layer promotion, video scripts, or SDR/HDR classifier: only the appended v0.3.8 context-menu CSS rules and Sine option label are replaced.
- The menu rule stays default-OFF and requires macOS Firefox-rendered menus (`widget.macos.native-context-menus=false`). Existing HG overlays can still cause temporary HDR dimming or washed out video when visible, which should recover when closed. No new `will-change`, video compositor workaround, or timer is introduced. The pre-existing Bilibili immediate glass rule still deliberately bypasses SDR/HDR detection.

## Validation and hardware limitations

- GitHub CI runs all Node.js regressions, JavaScript syntax checks, release-policy tests, and deterministic scheduling benchmarks before publishing. New v0.3.9 checks target the actual Firefox popup CSS variables, the removed opaque underlay/black corner border and native shadow, and preservation of Context Menu selection and HG existing blur/opacity values.
- **Actual macOS OLED SDR/HDR rendering acceptance not performed by CI.** Test a white GitHub page, a dark YouTube page, a high-contrast/textured area under a context menu, a nested submenu, the four corners, keyboard/mouse selection and existing menu-item ordering. True glass blur across an independently composited Firefox popup remains unverified and is not guaranteed. Do not infer macOS backplate blur from an all-white page. Check that SDR/HDR brightness, 10px first-frame sidebar/cards and PiP are unchanged.

## Rollback

- The new Sine context-menu option stays **default-OFF**. To revert only this appearance, switch OFF `mod.compacttpr.contextmenuglass` in Sine; preserve Zen Context Menu MOD and its `Zen's own menus on macOS` option, so menu ordering stays intact. If desired, return its optional gradient/accent background settings to their previous values. Restart Zen only if CSS does not refresh immediately.
- Full rollback: install [v0.3.8](https://github.com/kcussiefil/Zen-Compact-Transparent-HDR-Guard/releases/tag/v0.3.8), SHA `62b84ab9f17e0dcad2935649b4b9b07be7e58fc5`; backup branch `backup/v0.3.8-before-v0.3.9`. Historical tags remain intact.

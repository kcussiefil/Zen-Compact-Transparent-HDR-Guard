# Zen Compact Transparent HDR Guard v0.3.5 — Stable sidebar glass when YouTube starts

## Changes

- Prevent a video-state-dependent change of CSS ownership over the floating sidebar's Zia background underlay. When YouTube changes from page loading to actual playback, Zia's window marker `[zia-video]` can flip. Previously Zia supplied the transparent blurred underlay before this marker, while HG's video-only override took over afterward. Both use the same native 28px underlay values, but the CSS rule swap is a plausible cause of a one-frame brightness flash.
- The unified HG theme now applies one stable underlay rule scoped to `#navigator-toolbox .zen-toolbar-background` **before and after** Zia video detection. Its transparent background, 28px native support blur and Zia opacity factors are byte-equivalent to the existing pre/post-video appearance. HG's actual `#titlebar::before` custom blur and transparency — for example your 10px setting — remain unchanged and do not wait for video classification.
- The separate video-only fallback retains its previous behaviour outside the floating navigator toolbox. URL/new-tab popups, Zia/Site Folders cards, Glance v0.3.4 handling, sidebar sizing and YouTube/PiP page DOM are untouched. No PiP black-bar fix is attempted in this release.

## SDR/HDR and Zia compatibility

- This rule is gated by the existing main HG and unified theme preferences and `zia.compact.sidebar-blur`. With Unified HG OFF, the exact v0.3.4 and older policies continue unchanged. The old SDR, HDR and Bilibili independent video controls keep their original settings and behaviour; Glance's repair remains default-OFF.
- The repair changes **only the style ownership of an existing floating sidebar layer**; it does not add or prolong any `will-change: transform` compositor promotion, modify video actors, affect video resolution, or force an HDR colour/brightness filter. As previously accepted, HDR may become dim while an HG overlay is open; normal video brightness should recover on closure.
- Gecko and macOS can still perform a distinct native video-layer promotion when decoding begins, which CSS alone might not make flicker-free. This release removes a specific CSS discontinuity; complete flash elimination must be judged from real-device recording.

## Validation and hardware limitations

- GitHub CI must pass the complete Node.js test suite, syntax checks, 60-second virtual-time scheduler benchmark, 10,000-preview source-style comparison, and new 0.3.5 tests verifying fixed underlay styling for unknown/SDR/HDR playback states, Zia blur-pref gating, unchanged actual HG custom blur, isolation to the navigator toolbox and no new compositor request.
- **Actual macOS OLED HDR/SDR hardware verification not performed.** CI does not measure Gecko compositor state, frame luminance, user-visible blur transitions or GPU cost. In Zen, enable the unified theme and matching Zia sidebar blur, set custom HG blur to 10px, and reproduce a fresh YouTube playback load while the floating sidebar is shown. Compare before-play, first playing frame, pause/resume, SDR, HDR, closed sidebar and Glance. If the same luminance flash persists, report the recording; it may be a native video-layer transition rather than this CSS issue.

# Zen Compact Transparent HDR Guard v0.2.8 — Fix selected-color editor blur and enforce release consistency

## Changes

The v0.2.7 selected-tab color dialog still showed underlying GitHub text through its surface intermittently. Inspection of the user-provided macOS screen recording and Zen Site Folders 0.7.6 implementation confirmed that the dialog was styled with CSS `backdrop-filter`, but unlike Zia's hover cards it did **not** activate the browser-layer composition required for true macOS webpage blur.

- Restore proper glass behind Site Folders' **選取分頁顏色** non-modal dialog by applying Zia's established macOS composition technique **only while `#zsf-color-dialog[open]` exists**.
- The condition is removed as soon as Site Folders closes the editor. No timers, content observers or persistent layer promotion are added.
- Keep `opacity: 1` for the editor's actual element and preserve the HDR Guard-configured background color, background transparency and blur strength.
- Preserve Site Folders' own picker functionality, positioning, preview, focus, reset, cancel, save and selected-tab color/opacity choices. No files in the Site Folders repository were changed.
- Keep the sidebar visible while its color editor holds it open, including the `data-zsf-color-sidebar-hold` state in HDR Guard's existing HDR sidebar visibility gate.
- Align English and Traditional Chinese README version labels, the concise CHANGELOG and this release with the version in `theme.json`.
- Expand the release policy and automate its format/version checks, requiring all syntax and regression checks to pass **before** the GitHub Release is published.

## SDR/HDR and Zia compatibility

- Requires the existing default-OFF **「預覽卡片與選取分頁顏色視窗跟隨 HDR Guard 毛玻璃」** option and Zia's `zia.cards.blur` preference. No additional option or user migration.
- Under macOS, the webpage layer is promoted only for a visibly **open** editor and only on ordinary pages, confirmed/opted-in SDR, confirmed/opted-in HDR when Zia permits Blur over video, or the existing explicitly authorized Bilibili immediate-glass exception.
- Zia root `[zia-video]` remains a **hard exclusion**. Unknown/protected video never gains an extra custom compositor.
- HDR can still appear dim or washed out **while** the editor is open because of Gecko/macOS compositing. Closing the editor removes the new composition condition, but GPU and OLED recovery require actual hardware testing.
- Zia 2.118 and Zen Site Folders 0.7.6 behavior, Bilibili `www.bilibili.com/*`, the URL popup, native cards, animations and all user preferences remain otherwise unchanged.

## Validation and hardware limitations

- Automated verification: Node.js syntax checks, previous 019–027 suites, new 028 open-only compositor and HDR-gating tests, and automated release-policy/document consistency checks. These tests must pass in CI before merge and are repeated by the publisher.
- Device acceptance: compare the color editor on a regular GitHub page before and after hovering the editor; background text should stay blurred instead of becoming sharply visible. Confirm selecting a color and pressing Save/Cancel still work.
- HDR acceptance: play an HDR video, open and close the color editor, and verify the video returns to its normal HDR tone after closing. A temporarily dimmer image **while open** is expected with native Zia Blur over video. **Physical macOS OLED/GPU verification was not performed; automated CI cannot validate actual HDR brightness or video-layer recovery.**

# HDR Guard v0.2.7 — Site Folders selected-tab color dialog glass parity

## Why the editor was different
Zen Site Folders 0.7.6 creates a separate non-modal `<dialog id="zsf-color-dialog">` for **選取分頁顏色**. HDR Guard 0.2.6 styled tab/folder preview cards but did not target this dialog. Site Folders' dialog independently uses a 78%-opaque Zia card background, `blur(24px) saturate(1.45)`, so it looks different and may show background content through the panel.

## Change
- Reuse the existing **預覽卡片跟隨 HDR Guard 毛玻璃** Sine option (now explicitly describes the selected-tab color dialog). **Default remains OFF**; no new user setting or migration.
- When the option and upstream `zia.cards.blur` are ON, the selected-color editor uses **exactly the same background color, transparency and blur radius** as the HDR Guard sidebar, URL popup and existing card previews.
- Override only the **open** non-modal dialog `#zsf-color-dialog[open]` as a direct document-root child. Give it stable `opacity: 1` on hover/focus so that only its configured background color remains translucent; user-controlled opacity is retained via `color-mix`.
- Correct CSS specificity to override Site Folders' fixed `background: ... !important` and `backdrop-filter: ... !important` without modifying the Site Folders codebase or introducing competing rules there.
- Keep **picker functionality** (selected color, opacity slider, live preview, reset, save/cancel, close, positioning, keyboard focus, sidebar hold) entirely in the Site Folders MOD. Only **visual styling** belongs to HDR Guard.
- Preserve Zia / HDR Guard normal page, confirmed SDR, opted-in HDR and explicitly authorized Bilibili fast-path behavior. Unknown or protected video is not promoted into custom glass.

## HDR safety
**No extra video-compositor rules, brightness/color filters, event observers, or persistent layer promotions.** The new CSS does not set `will-change`, `backface-visibility`, `visibility`, `transform`, or dialog `display`/geometry. A visible color dialog may still rely on Gecko/Zia's current compositor behavior; macOS HDR brightness recovery must be tested on the user's OLED hardware. Static regression tests do not prove GPU rendering on video.

## Validation
Run all Node.js syntax and regression suites, including new checks for style-value parity, highest-specificity selected-color dialog rule, open-only scoping, opacity stability, Zia preference gating, and no new HDR compositor side effects. Verify with the editor open over a standard webpage, then hover/click inside it to ensure its background does not disappear. Test closing it during SDR/HDR playback.

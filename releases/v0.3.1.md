# Zen Compact Transparent HDR Guard v0.3.1 — Event-first performance without visual compromise

## Changes

- The exact HG v0.3.0 sidebar **blur radius, transparency, colour, height**, all other `chrome.css` visual rules, and every Sine preference/default are unchanged and byte-hash tested. HG never deliberately hands selected visual styling to the fixed Zia blur while a known, unchanged SDR/HDR tab is switched back into view.
- Replaced the chrome classifier's constant **50 ms (20/s)** render/probe loop with a **1000 ms (1/s)** fallback watchdog. TabSelect, navigation, actor stream changes, Zia root video changes, Bilibili fast-path changes and observed Sine preference changes render synchronously and request an immediate actor probe. The watchdog only recovers missed notifications; it is not a UI response timer.
- The explicitly configured unknown SDR site-rule fallback remains exactly **100 ms** via a dedicated one-shot timer; it does not wait for the 1000 ms watchdog. Confirmed HDR still wins, and unknown streams on non-whitelisted sites still fail closed.
- Duplicate actor snapshots no longer trigger redundant chrome rendering; unchanged root SDR/HDR marker values avoid needless DOM writes. The video content actor's **180 ms** periodic protection remains unchanged to preserve current-stream detection behavior.
- With the **default-OFF** Zen Glance correction disabled, its DOM MutationObserver is disconnected; preference changes reconnect/disconnect it immediately. When enabled, Glance recovery and its video/HDR safety conditions are unchanged.

## SDR/HDR and Zia compatibility

- HG custom appearances remain authoritative for the conditions enabled in Sine. Zia still controls its own native compositor and Blur over video policy, and no pixel-level CSS properties were altered. Video classification must still distinguish actual selected stream SDR/HDR from the monitor's HDR mode.
- **Bilibili** immediate-glass remains the documented user-controlled exception that bypasses stream classification and therefore could apply blur over HDR. The separate manual site-rule uses the existing 100 ms deadline and confirmed HDR always takes priority.
- The 180 ms child-actor monitor is intentionally unchanged. Unexpected media/player changes can still take the browser/Gecko time to detect; unknown or novel media formats cannot be forced into custom SDR without reducing HDR protection.
- If Zia Blur over video is enabled, macOS may render real HDR media **dim or washed out**; this v0.3.1 CPU/work scheduler change does not claim to repair the underlying macOS/Gecko compositor.

## Validation and hardware limitations

- GitHub CI runs Node.js syntax checks, all regression tests (including exact CSS/preferences/actor hash parity), plus the deterministic virtual-time side-by-side benchmark in `benchmarks/compare-v030-v031.cjs`. The comparison executes the real v0.3.0 baseline code (pinned under `benchmarks/`) and the current v0.3.1 code against the same mock DOM, actors and virtual clock for ordinary, stable SDR and repeated-tab-switch workloads.
- **Theoretical scheduler reduction:** chrome watchdog checks fall from 20/s to 1/s, or **95% fewer periodic callbacks / 20× fewer periodic checks**. The independent content-side video scanner remains at 180 ms (~5.56/s per running video actor). This counts scheduled work, not real CPU/GPU time or Zen UI animation speed.
- All virtual-time results are model-specific. **Actual macOS OLED HDR/SDR hardware testing was not performed** by Node.js CI. The release needs actual Zen/Zia/Site Folders tests for sidebars, video SDR/HDR, mid-playback quality changes, Glance open/close and no Zia-to-HG blur flicker. Neither 95% fewer callbacks nor the virtual wall-clock time is a claim of 95% faster sidebar animation.

## Rollback

- For an isolated Glance issue, turn the **default-OFF** `mod.compacttpr.glanceglass` option OFF in Sine and restart Zen if the native GPU layer state remains corrupted.
- For any regression, restore the immediate prior release **v0.3.0** at https://github.com/kcussiefil/Zen-Compact-Transparent-HDR-Guard/releases/tag/v0.3.0. Its immutable release commit is `41b7d91acefa875ebd824183a01932ad9ed85d62`.
- The separate backup branch `backup/v0.3.0-before-v0.3.1` remains fixed at `41b7d91acefa875ebd824183a01932ad9ed85d62`. To restore all earlier timings and code, install the full v0.3.0 release, not merely changing a Sine preference.

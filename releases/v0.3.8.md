# Zen Compact Transparent HDR Guard v0.3.8 — Opt-in macOS context-menu HG appearance

## Changes

- Add default-OFF mod.compacttpr.contextmenuglass, scoped to non-native Firefox/Zen macOS right-click context menus and nested submenus. This requires the user to manually set widget.macos.native-context-menus=false in about:config and keep HG enabled.
- Menu tint is derived from the current HG/Zen colour, transparency from mod.compacttpr.transparentvalue and first-frame best-effort blur from mod.compacttpr.customblur, including the user's 10px setting. A dark colour mix protects readability on white pages when the separate popup compositor cannot actually blur the underlying webpage.
- No global popup override, new JavaScript, menu reordering, hidden items, mouse hooks, timers, animations or browser-layer promotion.

## SDR/HDR and Zia compatibility

- Existing v0.3.7 HG sidebar geometry, Zia/Site Folders cards, URL popups, Glance, PiP and video detection code is unchanged. This CSS-only feature never changes will-change or backface-visibility on webpage layers.
- Existing Zia/HG glass overlays can still temporarily make HDR dim or washed out while visible; the display should recover once the overlay closes. This new default-OFF context menu does not change the compositor paths. The deliberate Bilibili instant-glass exception still bypasses SDR/HDR detection.

## Validation and hardware limitations

- GitHub CI runs Node.js regression and syntax tests, release-policy checks and deterministic benchmarks before publication. The new v0.3.8 test covers the pref default, macOS non-native restriction, explicit context-menu selectors, HG colour/opacity/blur and no video or menu-function changes.
- Actual macOS OLED HDR/SDR hardware testing not performed by CI. True native compositor blur on white GitHub or dark YouTube right-click menus is not verified. Test those pages, submenus, sidebar first frame at 10px, PiP and HDR brightness after menu close. The default-OFF switch leaves existing users unaffected.

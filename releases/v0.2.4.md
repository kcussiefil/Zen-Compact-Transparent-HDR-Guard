# HDR Guard v0.2.4 — Immediate Bilibili glass at www.bilibili.com/*

This release fixes the visible delay on Bilibili where the sidebar first appeared with Zia's native blur and then switched to HDR Guard after streamer classification.

## Behaviour
- Exact match **www.bilibili.com/** with any path (the requested `www.bilibili.com/*`), including homepage, videos, bangumi, and search pages, applies custom sidebar glass **immediately on selected-tab/navigation events**.
- Completely bypass SDR/HDR classification for the Bilibili glass decision when the new **Bilibili 全站立即使用自訂毛玻璃** option is enabled (**default ON**). This does NOT mark Bilibili content as SDR.
- Removes the former 50ms/350ms waiting-dependent Zia-native-to-HDR-Guard visual transition. The DOM marker is set synchronously on TabSelect and onLocationChange, not after a polling or network request.
- Changes the default manual fallback site rule to **www.bilibili.com/*** (previously two narrower paths). Existing Sine user-edited values may be retained by prefs, so update the field manually if needed.
- The override is constrained to the exact www.bilibili.com hostname (not other Bilibili subdomains or lookalike hostnames).
- **Only active when Zia's Blur over video is ON.** If OFF, keeps native Zia video protection.
- Other websites (including YouTube) retain the full HDR/SDR classifier and all prior 0.2.3 functionality.
- Bilibili URL/search popup also uses custom HDR Guard style immediately IF the independent 0.2.3 popup checkbox is enabled.

## HDR caveat
The user deliberately authorizes Bilibili bypass regardless of whether the stream is HDR or SDR. Actual HDR video on Bilibili may therefore dim or lose HDR when Zia blurs video behind an open overlay. The MOD does not force a persistent browser compositor layer or add any brightness compensation; compositor visibility remains Zia-owned, including when the sidebar is hidden.

## Verification
- GitHub Actions: JavaScript syntax, all existing regression suites, new synchronous navigation/pref-change tests and exact-domain scoping tests.
- macOS 27.2 + OLED device validation: from a normal website, switch directly to www.bilibili.com/* with sidebar open; confirm no Zia-native flash. Navigate between homepage/video/bangumi. Confirm leaving Bilibili restores the correct style and closing the sidebar leaves HDR video undimmed.
- The actual macOS video blur / HDR color cannot be proven with Node tests.

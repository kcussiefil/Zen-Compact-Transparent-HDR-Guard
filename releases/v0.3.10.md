# Zen Compact Transparent HDR Guard v0.3.10 — Restore macOS context-menu background safely

## Changes

- Fix the confirmed v0.3.9 regression where the entire non-native right-click menu background disappeared while text, icons and selected-item highlight remained. On real macOS Firefox/Zen, deleting both popup `appearance` and its `Menu` background removed the only reliably painted menu backplate. v0.3.10 **removes the forced `appearance: none`, `-moz-default-appearance: none`, and `background-color: transparent` declarations**; it does not depend solely on `::part(content)` being composited.
- Add explicit **visible dark HG-tinted background with an rgba(28,28,31,0.93) fallback** to the menu host, Firefox's actual `--panel-background-color` variable, and the popup-content part. The host retains a rounded background. The current HG colour, transparency and blur variable (including user-set 10px) remain first-paint inputs wherever popup rendering supports them. These redundant protective surfaces are intentional for safety; their combined opacity may make the menu visually more solid than the sidebar. True cross-window blur and corner-shadow behaviour are not guaranteed by CSS or CI.
- Keep Zen Context Menu MOD installed and its **Zen's own menus on macOS** enabled to preserve preferred menu ordering, item hiding and icons. Only the optional background/paint of existing right-click menus is styled, not layout or commands.

## SDR/HDR and Zia compatibility

- All v0.3.9 HDR/SDR stream classifiers, sidebar geometry, Zia/Site Folders preview cards, Glance, video playback, PiP, URL popups and scripts remain byte-for-byte untouched. No new timers, observers, will-change promotion, GPU policy or video transition changes are introduced.
- As before, visible Zia/HG glass surfaces may make HDR temporarily dim or washed out on some macOS hardware; closing them should recover the full-brightness image. The deliberate Bilibili instant-glass option still bypasses SDR/HDR checks. This menu-only fix must not claim to resolve those unrelated video limitations.

## Validation and hardware limitations

- GitHub CI runs Node.js syntax, all regression tests, release-policy checks and deterministic performance benchmarks before publication. Dedicated v0.3.10 tests explicitly reject the three transparent-background resets responsible for the reported regression and require a concrete host and popup-content fallback, while preserving Zen Context Menu compatibility.
- **Actual macOS OLED SDR/HDR hardware visual testing has not been performed by CI.** Unlike v0.3.9, the intended popup now has a visible fall-through background even when its shadow part is unsupported, but actual foreground/background blending, the four corner outlines, HG 10px visual blur and nested menus remain unverified on the user's Zen. Test over white Shinkansen, dark pages and a textured image; do not treat flat white as a useful indicator of background blur. Test item ordering, YouTube SDR/HDR brightness and PiP before declaring acceptance.

# Zen Compact Transparent HDR Guard v0.4.1 — macOS context-menu window-shadow isolation test

## Changes

- **Single-variable experiment:** remove only `-moz-window-shadow: none !important;` from the v0.4.0 scoped right-click menu CSS. The v0.4.0 switch made ordinary context-menu backgrounds invisible on the user's macOS Zen setup, despite removing all explicit background overrides. The window-shadow override may affect the system-drawn menu backplate; this release tests that hypothesis without claiming a proven fix.
- Preserve the other scoped CSS declarations **exactly**: `--panel-border-color: transparent`, `--panel-box-shadow: none`, `::part(content) { border-color: transparent; box-shadow: none; }`, the original selectors, and the same default-OFF Sine setting `mod.compacttpr.contextmenuglass`.
- **No new Site Folders menu selector in this round.** The custom `#zsf-site-group-menu` is also a Gecko XUL `menupopup` but is a different menu from regular `#tabContextMenu`. It should be considered after confirming the general menu's backplate. Zen Context Menu's ordering and hover behaviour remain managed by the original mod. This release does not attempt the rounded-corner black-outline cure beyond the unchanged v0.4.0 border rules.

## SDR/HDR and Zia compatibility

- No changes to HG/HDR/SDR compositing, classification, Zia cards, the sidebar, Glance, PiP, Site Folders drag behaviour, scripts, preferences, or timers. This experiment affects only the macOS user-toggle menu CSS.
- Zia/HG blur over video can still make HDR temporarily dim or washed out while an overlay is visible; this experiment does not address video brightness. The Bilibili immediate-glass exception still bypasses HDR checking when enabled.

## Validation and hardware limitations

- GitHub CI runs Node.js tests, syntax checks, the complete regression suite, the release policy gate, and deterministic simulations. Added/adjusted regression assertions ensure `-moz-window-shadow` is absent from the context-menu block while every remaining v0.4.0 border/shadow declaration and the disabled-by-default opt-in switch remain.
- Actual macOS 27.2 OLED rendering **not verified** by CI or the author in the user's Zen installation. A CSS/static test cannot tell whether the invisible native popup background is restored. Keep Zen Context Menu's `Zen's own menus on macOS` active (`widget.macos.native-context-menus=false`), then enable HG's **default-OFF** menu option and check ordinary page and tab right-click menus on white and dark pages, plus nested submenus. Report whether the background is restored and whether the four corners still have black lines; turn the switch OFF immediately if the popup background disappears.
- A success on ordinary menu backgrounds does not verify Site Folders menu coverage; it intentionally remains outside these selectors until the root cause is confirmed.

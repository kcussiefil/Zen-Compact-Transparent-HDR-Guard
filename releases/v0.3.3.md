# Zen Compact Transparent HDR Guard v0.3.3 — Unified first-frame HG glass across overlays

## Changes

- Added **Unified HG theme**, a single reversible Sine checkbox **default-ON**. When the main HG floating-sidebar glass setting and Zia's corresponding surface blur preference are enabled, the floating sidebar, Zia tab/folder/tip cards, Site Folders group card/color editor, URL/search popup and Zen floating new-tab URL bar immediately use the user's existing HG background colour, transparency and blur (for example 10px). They do not wait for a video to be identified as SDR or HDR, and they do not intentionally render Zia 24px or HG's absent-preference fallback 5px first.
- The Zia requirements remain explicit: `zia.compact.sidebar-blur` for the sidebar, `zia.cards.blur` for cards, and `zia.urlbar.pop-up-blur` for URL/new-tab popups. The previous separate HG per-surface options retain their prior values and only govern the old policy while Unified HG is OFF. If a matching Zia option is OFF, this version does **not** force its corresponding visual surface.
- A hidden native Zia card gets HG's CSS values before Site Folders synchronously samples it, but remains `display:none`; preview positions, animations, row geometry and controls are not changed.
- In Zia's opposite-palette single-toolbar popup mode, HG's **blur and opacity** remain active while the popup's matching Zia colour is retained to protect text contrast. This avoids switching to Zia's solid/no-blur exception without forcing unreadable dark-on-dark or light-on-light text.
- The v0.3.2 policy is a one-click fallback: turn **OFF** `mod.compacttpr.unifiedhg` in Sine. The previous standalone SDR, HDR and Bilibili controls remain unchanged.
- The legacy standalone HDR-video override remains **default-OFF**; the new unified mode deliberately makes a separate, clearly documented appearance-first tradeoff.

## SDR/HDR and Zia compatibility

- macOS Firefox/Zen renders page video on a separate compositor layer. Merely setting `backdrop-filter` may yield an apparently transparent overlay without blurred webpage pixels. Unified HG therefore requests the same `will-change: transform` composition technique used by Zia **only while** a matching sidebar, visible preview card, Site Folders color editor, URL/search or floating new-tab popup is open. The new selector matches its corresponding Zia blur preference; it does not promote a disabled feature or a hidden source card.
- This is an explicit appearance-first choice. An **unknown**, SDR or HDR video may become **dim or washed out** on macOS while an HG overlay is open, including when Zia's usual video safeguard would leave the surface unblurred. Closing all relevant overlays immediately removes HG's added compositor eligibility; actual HDR brightness restoration and GPU teardown timing must be verified on the user's macOS system. No background video by itself keeps this rule active.
- Glance retains its separate, previously protected composition and recovery path. The new overlay compositor rule excludes an active Glance overlay; this deliberately avoids stacking two experimental video-compositor paths.
- The optional immediate Bilibili glass exception still bypasses stream classification. The video classifier, SDR/HDR state markers, Bilibili URL detection, 1000ms watchdog, independent 100ms site fallback and 180ms media child checks are byte-identical to v0.3.2.
- There remains a hardware limitation: if the compositor fails to provide actual page pixels despite its visible-only promotion, CSS alone cannot certify true background blur. The configured HG colour/opacity remains as the readability background; users should avoid nearly 100% transparency over video.

## Validation and hardware limitations

- **Node.js CI requirements:** complete regression suite, source-preserving v0.3.2 opt-out parity, JavaScript syntax checks, 60-second virtual-time scheduler benchmark, 10,000-preview first-frame comparison and the new v0.3.3 root-state/visibility preference tests. No JavaScript, observer, actor probe or interval was added; the change is CSS and a Sine preference.
- The new tests check all four visible surface categories, hidden Zia card computed-style eligibility, explicit matching Zia settings, unknown video appearance that does not wait for classification, visible-overlay-only compositor selection, and full restoration of prior CSS/pref bytes when Unified HG is OFF.
- **Hardware verification not performed:** the Node.js model and CI do not measure actual macOS OLED HDR/SDR, first rendered frame, Gecko `backdrop-filter`, GPU performance, HDR brightness restoration or ghost text behind a popup. A headless Chromium attempt in the cloud development sandbox was blocked by process/socket permissions; that is not evidence of visual success.
- **On-device acceptance:** use HG blur 10px and the preferred custom transparency. Repeatedly open/close the floating sidebar, Zia native card, Site Folders group card, URL/search popup and new-tab floating bar over (1) a normal webpage, (2) SDR YouTube, (3) 4K HDR YouTube, and (4) an unknown-format stream. Verify no Zia 24px → HG 10px transition, no unreadable webpage text through unblurred transparency, no persistent HDR dimming when all overlays are closed, no Glance regression, and no obvious latency/scroll performance regression. Treat any failure as a release-blocking hardware concern for wider adoption.

## Rollback

- **Immediate visual rollback:** turn **OFF** the default-ON `mod.compacttpr.unifiedhg` option in Sine. Every prior v0.3.2 CSS rule and all legacy HDR/SDR/popup/card settings remain intact and effective.
- **Full rollback:** reinstall the previous [v0.3.2](https://github.com/kcussiefil/Zen-Compact-Transparent-HDR-Guard/releases/tag/v0.3.2), full commit `1e7099d44908a4c118216c86cf4e3cac0e7396bb`. Recovery branch: `backup/v0.3.2-before-v0.3.3`. Restart Zen after changing the installed Sine MOD version.
- If the unified setting is ON but a specific overlay is not HG-glass, verify the corresponding Zia blur preference before changing any video or compositor setting.

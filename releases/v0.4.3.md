# Zen Compact Transparent HDR Guard v0.4.3 — background-tab compositor isolation experiment

## Changes

- **Retire the failed v0.4.2 card-level `will-change: backdrop-filter` hint.** The user reported that background-tab loading still caused Zia and Site Folders preview cards to lose their blur, including with HG disabled. Do not keep an ineffective extra GPU layer on the card.
- Reuse the **same default-OFF** Sine preference `mod.compacttpr.previewcardstability` (renamed in the UI to describe the new behaviour). When a Zia tab/folder/tip card or Site Folders group card is actually visible, suppress Zia's `will-change: transform` promotion **only on inactive background browser panels** via `will-change: auto` and restore their `backface-visibility` to `visible`. Zia's existing CSS promotes all browser panels while a native card is visible; unloading background layers may reduce compositor churn during background-tab creation.
- The **currently selected** `.deck-selected` pane and all **split-view** `[zen-split="true"]` panes keep their original compositor promotion. The rule is limited to macOS, enabled HG unified theme, and Zia's own cards-blur preference. It is disabled in DOM fullscreen/customizing, when root `[zia-video]` applies video protection, and when selected Glance overlay is present; Glance surfaces are excluded as targets. Native blur amount, HG user-configured 10px, card transparency, menu background, animations and geometry stay unchanged.
- This is a new **testable hypothesis, not a confirmed rendering fix**; no Firefox/Zen/Zia or Site Folders files are altered.

## SDR/HDR and Zia compatibility

- Existing Zia and HG selected-pane, sidebar and URL-popup promotions remain unchanged. Do not alter Zia SDR/HDR detection, video actors, PiP, playback, script timing, card paint, Sine's user blur values or the v0.4.1 right-click menu. The known **dark corner outlines** of non-native macOS right-click menus remain unresolved; the menu background and submenus had been confirmed working in v0.4.1.
- HDR can still be dim or washed out during Zia/HG glass over video. The Bilibili instant-glass option still deliberately bypasses HDR detection when enabled. Test HDR and SDR video separately; this experiment does not claim to preserve HDR brightness.

## Validation and hardware limitations

- GitHub CI must pass Node.js syntax checks, full Node regressions, release policy verification and deterministic benchmark simulations before publishing. New static tests check that the ineffective v0.4.2 card hint is removed, the new selector excludes selected/split/Glance and root protected video states, the background-panel `will-change` change is visible-card-only, and the 0.4.1 menu background restoration stays intact.
- **Actual macOS 27.2 OLED hardware testing not performed by CI.** CSS tests cannot prove that the computed GPU layer actually resolves the backdrop-filter problem. In Sine, turn the same default-OFF macOS preview-card-stability switch ON, keep unified HG and Zia cards blur ON, and compare OFF vs ON on the same browser profile while opening multiple links **in background tabs**, first with Zia's own tab/folder hover cards, then with a Site Folders group hover card. There must be **no clear/unblurred flash** during page creation, loading, or load completion; user-set 10px blur, card transparency, sidebar, video and navigation must remain consistent. If this fails, switch it OFF and capture a DOM/computed-style trace before any further CSS workaround.
